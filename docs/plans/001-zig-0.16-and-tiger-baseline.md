# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Move zuda from Zig 0.15.2 to 0.16.0 with the kingdom `io: Io` convention
(`citadel/core/rules/zig-0.16.md`) on every public function touching time, fs or thread sync;
add a `tidy` gate to `zig build test`; ship the signature break as **v3.0.0**.

## Why now

- ROADMAP Phase 1 puts zuda in the second wave (with sailor, after the sigil spike settles the
  `io: Io` shape). zr, silica and zoltraak are blocked behind zuda v3 + sailor v3 and get no
  real `zig build` signal until zuda's `build.zig` compiles on 0.16. zuda itself depends on
  nothing (`.dependencies` is empty): every item below is `blocked_by: none`.
- Probe: `build.zig` fails first on `Compile.linkLibC`; past it `zig test src/root.zig` gives
  **44** errors in 5 classes — `std.time.*` 21, `ArrayList` `.{}` 18, `std.fs.cwd()` 14,
  `AutoArrayHashMap` 2, `std.io` 1 — undercounted: 20 more files touch `fs`/`Thread`/`time`/
  `posix`/`io` outside root's test graph.
- 445 files / 461,635 LOC, 76 over the repo's own 800-line rule: Tiger Style holds here only by
  ratchet. And 92 commits sit unreleased behind a README claiming "8 distributions, 4600 tests"
  (actual: 209, ~22k).

## Out of scope

- Splitting `distributions.zig` (128k lines, 11.7k tests) by family — the biggest lever on CI
  time, but its own plan; here it would swamp every migration diff. Likewise the 209 legacy
  3-arg `format()` impls, the `catch unreachable` audit (69 sites) and the two `p < 1e-300` f32
  underflow sites: recorded in the `tidy` allowlist, ratcheted down later.
- New distributions or algorithms; consumer migrations (they adopt the v3.0.0 tag themselves).

## Risks

- **Undercounted breakage.** 44 is what one compilation unit reached; 20 I/O-touching files
  never enter `root.zig`'s test graph — items are split per class and module to contain spill.
- **Test-suite cost.** The full suite is 8–10 min, dominated by `distributions.zig` — iterate
  with `zig test <file>` / `--test-filter`, run it whole once before each merge.
- **Wrong `io: Io` shape.** Threading `io` through ~60 container APIs *is* the v3.0.0 break and
  getting it wrong costs a v4 — hence one item fixing the shape on a spike first.
- **Platform-specific concurrency.** `LockFreeStack`/`LockFreeQueue` need 128-bit atomics and
  are macOS-only by design; CI cross-compiles 6 targets but only *runs* the host's — read
  `memory/debugging.md` before "fixing" them.
- **Benchmark drift.** LLVM loop vectorization is off in 0.16; numeric regressions here are the
  toolchain's, not the code's — do not chase them.

## Version impact

**MAJOR → v3.0.0.** `std.Io` changes public signatures across the container, ndarray and
parallel APIs (`io: Io` after the receiver), so dependents must be edited, not just recompiled.
Consumers: zr, silica, zoltraak — each gets a migration issue at release.
